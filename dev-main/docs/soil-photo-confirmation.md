# Наблюдения по фото и подтверждение в диалоге

Фотоописатель теперь запрашивает структурированный результат: вид объекта,
ограничения качества/цвета и до семи видимых признаков. Название типа почвы,
проценты уверенности, pH, NPK, соли, натрий и глубины не входят в этот формат.
Неизвестные поля ответа модели игнорируются. Для вызова фотоописателя включён
режим JSON в Ollama; обычное OCR и генерация ответа не переводятся в этот режим.
Подпись музейного монолита не подставляется вместо морфологии. Отдельный
повторный вызов зрения не добавлен.

## Пример беседы

1. Посетитель прикладывает фото и сообщает регион. Модель предположительно
   видит отдельный светлый слой и рыжевато-бурый материал ниже него.
2. Помощник спрашивает только о светлом слое: действительно ли это слой внутри
   разреза, а не налёт на поверхности. Пока ответа нет, признак не участвует
   в выборе справочного направления.
3. Короткое «да» подтверждает только этот признак. Следующий вопрос может
   уточнить рыжевато-бурый слой под ним. Его подтверждение сохраняется отдельно.
4. В итоговом ответе основание отмечается как подтверждённое посетителем
   наблюдение по фото, без независимой проверки. В версии v4 двух цветов
   недостаточно для названия подзола: итог объясняет ограничения и необходимые
   различения процессов. Название допускается при диагностических данных.

«Нет» и «не знаю» не становятся положительными признаками. Эти уточнения
повторно не задаются. «Да, наверное», «да?» и «да, но это другой образец» не
считаются однозначным подтверждением. Фраза «другой образец» теперь, как и
«другой участок», явно начинает сбор заново.

Изображение без ответа посетителя по-прежнему не даёт доказательств для
сопоставления. Оба признака из одного фото нельзя подтвердить единственным «да».
Регион запрашивается первым, если он неизвестен; сохраняется общий предел
трёх уточнений. При достижении предела итог может остаться неполным.

## Ограничения качества

- Структурированная запись имеет собственный SHA-256 нормализованного снимка,
  действительно переданного модели. Модель не может назначить этот идентификатор.
- Для предложений подтверждения нужны подходящий вид объекта и качество
  `usable`. Для цветовых признаков также нужны `color=natural` и отсутствие
  отметки об искажённом освещении. Это оценки модели, а не объективная проверка
  камеры или освещения.
- Снимок с короткой стороной меньше 160 пикселей или площадью меньше 65 536
  пикселей принудительно считается ограниченным по качеству независимо от
  ответа модели. Это инженерный порог для отсечения мелких изображений,
  не гарантия научной пригодности всех остальных фотографий.
- Размытые/ограниченные снимки не порождают такие вопросы подтверждения.
  Наличие масштаба не превращает визуальные признаки в измеренные глубины.
- «Рыжий слой под светлым» не предлагается к подтверждению, если светлый слой
  на этом снимке посетитель ещё не подтвердил. Это предотвращает повторное
  навязывание отвергнутого наблюдения под другим вопросом.
- Для фото инструкции/шкалы допускается отдельная непроверенная расшифровка
  текста. Она не становится анализом, который якобы сообщил посетитель.
- Старый текстовый ответ фотоописателя остаётся доступным как непроверенное
  описание, но не даёт структурированных признаков. Повреждённый JSON также
  не превращается в доказательства. Поддержка JSON реальной установленной
  моделью проверяется отдельно.

## Память и смена контекста

Карточка `soil_case` получает версию 4 без изменения таблиц SQLite. Старые
карточки версий 1–3 читаются. Хранятся до четырёх структурированных записей
фото, их хеши, ограниченный набор статусов и короткие ответы подтверждения.
При вытеснении записи её подтверждения больше не используются. Исходные
изображения в историю сайта по-прежнему не записываются.

Вопрос относится только к текущему снимку. Загрузка нового снимка не считается
ответом на старое подтверждение; неструктурированный новый снимок не запускает
вопрос о старом изображении. Подтверждённые ранее наблюдения того же участка
могут сохраняться в ограниченной памяти. Явная смена участка/образца сбрасывает
их полностью, смена темы снимает ожидаемое подтверждение. После запроса итога
произвольное «да» тоже ничего не подтверждает.

## Проверка на настоящей модели и единый отчёт

На компьютере с Ollama из папки проекта:

```powershell
python scripts/evaluate_photo_observations.py "C:\папка-с-тестовыми-фото"
```

Можно передать отдельный файл. По умолчанию выбираются до десяти JPG/PNG/WebP
в алфавитном порядке. Имена файлов не передаются модели. Каждое изображение
проходит те же ограничения и нормализацию, что на сайте. Скрипт использует
локальный `.env`, `OLLAMA_VISION_MODEL` и настроенный адрес Ollama. Настройки
аккаунтов, лимиты сайта и базу чатов он не меняет.

Результат — один HTML в `logs`, который можно открыть в браузере. В нём находятся
точные изображения на входе модели, хеши исходников и входа, наблюдения,
ограничения, ошибки по типу, версия кода, имя модели и время каждого вызова.
Подготовка изображения и вызов зрения измеряются отдельно; это клиентские
замеры данного скрипта. Файл сохраняется после каждого снимка. Существующий
отчёт не перезаписывается; другой путь задаётся через `--output`. При ошибке
вызова или отсутствии структурированного ответа код завершения — 1; частичный
отчёт при этом сохраняется.

Отчёт может содержать личные изображения и имена файлов: его создают только
явным запуском, он не публикуется и не отправляется автоматически. Папка
`logs` исключена из Git. При пересылке отчёта это следует учитывать.

Этот прогон **не измеряет** качество полного диалога, правильность таксона,
скорость сайта или ожидание в очереди. Имя модели не фиксирует её веса.
Для сравнения моделей дополнительно следует сохранить их версию/digest.
Нужны отдельная разметка видимых признаков, проверка почвоведом и повтор
полных десяти сценариев. При отсутствии экспертной разметки процент точности
не рассчитывается. Подставной тестовый ответ не является прогоном живой модели.

Обновлять нужно весь пакет, включая `soil_photo.py`, `files.py`, `performance.py`
и остальные изменённые файлы; локальные `.env` и `data/app.db` сохраняются.
После перезапуска версия `/health`: `semantic-soil-interview-v4`. Подробнее об
[исправлениях после повторного прогона](soil-evidence-fixes.md). В этой разработке живой
прогон на домашней GPU не выполнялся; установка и возможности конкретной
Ollama-модели должны быть подтверждены на компьютере владельца.
