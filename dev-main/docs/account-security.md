# Предупреждение Chrome и безопасность аккаунта

«Пароль найден в утечке» — результат проверки данных входа браузером по известным
утечкам. Само сообщение не устанавливает, откуда произошла утечка, и не доказывает
взлом TerraMind. Код сайта не может удалить этот результат из базы Google.
Автозаполнение, менеджер паролей и проверка Chrome остаются включёнными.

## Что делать пользователю

1. Войти в аккаунт и открыть «Пароль».
2. Ввести текущий пароль и задать новый уникальный пароль или длинную фразу.
3. Сохранить обновлённый пароль в менеджере Chrome, когда браузер предложит это.
4. Если прежний пароль использовался на других сайтах, заменить его и там.

После смены текущая сессия заменяется новой, остальные сессии отзываются. Чаты не
удаляются. Если старый пароль забыт, самостоятельное восстановление через email
в этой версии не реализовано: отправка писем не настроена.

## Реализация

Новые пароли имеют длину 12–128 символов. Локально отклоняются несколько типичных
распространённых паролей, повторяющиеся строки и совпадение с email. Это небольшой
список, а не полная база скомпрометированных паролей. Пароли не передаются внешним
сервисам для проверки. Нет требований добавлять заглавную букву или особый символ
ради галочки: длинные фразы допустимы.

Новые хеши — PBKDF2-HMAC-SHA256, 600 000 итераций и случайная соль. Существующие
хеши старого формата проверяются прежним способом и обновляются после успешного
входа. Это не меняет пароль и не отменяет необходимость заменить скомпрометированный
пароль. Данные и аккаунты не удаляются обновлением. При конкурентной смене пароля
вход с уже проверенным старым хешем не создаёт новую сессию.

Браузер получает сессию только через HttpOnly-cookie. Ответ JSON больше не содержит
её значения при браузерном запросе. Для прежних CLI-клиентов без Origin и
Sec-Fetch-Site сохраняется ответ с токеном. Защита Origin и специального заголовка
сохраняется для смены пароля; на неё также действует ограничение частоты запросов.

Убрано разрешение CORS для любых сайтов. Страницы и API текущего сайта работают
с одного origin; будущие внешние браузерные интеграции потребуют отдельной схемы
доверенных источников или reverse proxy. Применены CSP для same-origin ресурсов,
запрет встраивания в чужие фреймы, nosniff, no-referrer и no-store для чувствительных
маршрутов, включая ошибки. Интерактивные Swagger/Redoc страницы отключены; JSON
`/openapi.json` остаётся доступным для технических проверок.

Стандартные ошибки валидации не возвращают поле input, которое могло содержать
отклонённый пароль. Ошибки, ключи, пароли и полные тела запросов не добавляются в
журнал этим обновлением.

Тела запросов ограничиваются до разбора JSON/multipart: 8 МиБ для вопросов с фото,
11 МиБ для административной загрузки, 2 МиБ для /knowledge и 16 КиБ для остальных
операций изменения. Ограничение проверяет и Content-Length, и фактические байты
потока. При этом прежние лимиты фотографий и документов продолжают действовать.

Это исправление выявленных слабых мест и проверка кода с тестами, а не заключение
об отсутствии всех уязвимостей или исследование возможного инцидента. Защита
компьютера, резервных копий, почты владельца и настроек Cloudflare остаётся
ответственностью оператора.

## Проверка

Python-тесты проверяют совместимость старых хешей, отзыв сессий, сохранность чатов,
гонку входа со сменой пароля, ограничения запросов, CSRF и отсутствие паролей в
ошибках. Браузерные сценарии проверяют форму и HTTP-заголовки через настоящий API
с тестовой базой и подменённой моделью; работа реальной Ollama не затрагивается.
