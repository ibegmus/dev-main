# Сначала выяснить причину ошибки

Последний живой прогон подтвердил краткость: 10 ответов по 35–55 слов,
медиана 46. Он не показал надёжного определения типов. На отдельных фото
гипотезы расходятся с подписями источников, видимая вода превращается в
«постоянное переувлажнение», а просьба сжать образец остаётся после слов
«у меня только фото». Эти три проблемы нужно оценивать отдельно.

## Контрольное сравнение на компьютере с Ollama

В облачной среде разработки нет доступа к домашнему `localhost` с моделью.
Поэтому здесь нельзя честно объявить, что прямой вызов модели на этих пяти
примерах уже проверен. Нужен локальный запуск; веса передавать не нужно.

После переноса новой версии проекта, включая папку `tests/fixtures/soil_ablation`,
в PowerShell из `C:\pochva-api` тем же Python, которым запускается сайт:

```powershell
python scripts/compare_soil_modes.py
```

По умолчанию сравниваются два снимка: 01 — исходник с подписью Podzol,
06 — с подписью Histosol. Получится **шесть обращений**, по три на снимок.
Ожидайте несколько минут; длительность заранее не фиксируется.

Три режима:

1. `native`: фото и слова посетителя, без системного промпта сайта и справочника.
   Пользовательское сообщение оформлено так же, как в `prompt_only`: отличается
   только наличие системной инструкции. Это не сравнение разных интерфейсов Ollama.
2. `prompt_only`: те же сведения и промпт сайта, без справочника.
3. `with_reference`: тот же промпт и справочник ответного этапа сайта.

Модель, думающий режим, температура, контекст и бюджет генерации одинаковы.
Скрипт использует существующую `OLLAMA_VISION_MODEL` и настройки Ollama проекта,
читает локальный `.env`, ничего не скачивает из моделей и не публикует.
Нет обращений к API сайта, расхода дневных запросов или создания бесед в базе.
Для чистоты времени желательно проводить сравнение без параллельных запросов
к Ollama; скрипт самостоятельно не останавливает сайт и процессы.

Результат — `report.html` и `report.json` в новой папке
`data/evaluations/soil-ablation-…`. HTML открывается двойным щелчком, содержит
фото, ответы, промпт, справку, порядок вызовов, хеши входов и метрики времени.
Внутренние рассуждения, пароль и значения переменных окружения не сохраняются.
Отчёт сохраняется после каждого ответа; при ошибке записывается её тип,
а не текст исключения с возможными секретами. Существующий отчёт не перезаписывается.

Для одного примера или более широкой проверки:

```powershell
python scripts/compare_soil_modes.py --case 6
python scripts/compare_soil_modes.py --all
python scripts/compare_soil_modes.py --case 6 --repeats 3
```

Все пять фото дают 15 обращений за один повтор. До трёх повторов помогают
проверить устойчивость результата; порядок режимов меняется между примерами
и повторами. Первый запуск может включать загрузку модели, поэтому время
загрузки приводится отдельно. Это время ответного этапа, без очереди,
первичного фотоописателя, маршрутизации и внешнего поиска.

В каждом запросе объединены исходный вопрос и последующие известные факты.
История разных ответов не добавляется: иначе второй ход уже содержал бы
разный контекст. Снимок нормализуется через тот же `decode_photo`, что на сайте.
Подписи, названия файлов и ожидаемые группы не передаются модели. Источники
и лицензии фотографий перечислены в `tests/fixtures/soil_ablation/cases.json`.

## Как оценивать результат

Для каждого ответа отдельно отметить основную гипотезу, альтернативу,
описание отдельных свойств, недостаточность данных и утверждения, которых
нет в исходных наблюдениях. «Глинистая» — это характеристика состава;
она не считается определением типа «солонец». Соответствие подписи фото
не заменяет экспертизу. Российские, WRB и канадские группы не равнозначны
автоматически; процент точности из этих пяти примеров не устанавливается.

- Если `native` устойчиво лучше `prompt_only`, исследовать влияние промпта.
- Если `prompt_only` устойчиво лучше `with_reference`, исследовать состав,
  релевантность и способ подачи справки. Сейчас добавляются все десять карточек.
- Если ошибки повторяются во всех режимах, следующий контроль — экспертное
  описание признаков вместо изображения при тех же фактах. Это поможет отделить
  визуальное распознавание от выбора типа и отсутствующих полевых данных.
- Один удачный или неудачный ответ не доказывает причину. Проверяются несколько
  примеров и повторяемость. Новый текст промпта не считается улучшением без
  повторения одинаковых проверок.

## Следующий этап полевого диалога

После сравнения нужен отдельный проверяемый сценарий сбора признаков:

1. Сохранять доступность участка: человек на месте, может проверить позже,
   располагает только фото либо доступность ещё неизвестна. Сведения берутся
   из его ответов, не из предположений модели. При смене участка контекст сбрасывается.
2. Разделять увиденное на фото, слова человека, результаты проб и гипотезы ИИ.
   Вода на одном снимке не устанавливает длительность переувлажнения; тёмный
   цвет сам по себе не измеряет органическое вещество.
3. При доступном образце предложить одну понятную пробу: слегка увлажнить
   небольшое количество земли, попробовать сформировать шарик и короткий шнур,
   описать результат. Это ориентировочная оценка состава, не установление типа,
   pH или потребности в удобрениях. Вопрос об обычном застое воды — отдельный.
4. Хранить, что уже спрашивали и что человек не знает или не может проверить.
   Не повторять недоступную пробу. При наличии только фото выдавать полезную
   предварительную оценку по доступным признакам.
5. Следующий вопрос выбирать ради различения оставшихся версий. Сама гипотеза
   остаётся ответом модели: не возвращать прежний движок, который блокировал
   название почвы до обязательного набора лабораторных признаков.

Этот этап не объявлен реализованным в данном изменении. Сначала нужен результат
контрольного сравнения, чтобы не закрепить ошибочную причину очередными правилами.

## Получен первый отчёт

Разбор шести реальных ответов от 16 ноября: [результаты и ограничения](soil-ablation-results-20261116.md).
Для следующего узкого сравнения добавлен необязательный режим `evidence_card`.
Он не включён для посетителей и не заменяет исходные три режима.

```powershell
python scripts/compare_soil_modes.py --case 6 --mode with_reference --mode evidence_card
```

Получится два вызова: прежний ответный этап и тот же этап с карточкой сведений
посетителя. В отчёте записывается точный добавленный контекст. Для проверки
устойчивости добавьте `--repeats 3`; результаты пока не измерены на модели.
