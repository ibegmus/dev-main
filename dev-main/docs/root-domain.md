# Адрес pochva-ai.tech без api

Маршрут туннеля уже должен содержать Published application с hostname `pochva-ai.tech`, пустым Subdomain и Path, Service URL `http://localhost:8000` (как на предоставленном скриншоте). Он обслуживает тот же сайт и базу аккаунтов.

Проверка публичного DNS 6 ноября 2026: NS — dimitris.ns.cloudflare.com и donna.ns.cloudflare.com; api.pochva-ai.tech возвращает адреса Cloudflare, корневой домен — без записи A.

## DNS в Cloudflare

1. Откройте управление зоной `pochva-ai.tech` → DNS → Records.
2. Найдите существующую запись `api`. Если это CNAME с Target вида `<UUID туннеля>.cfargotunnel.com`, скопируйте Target.
3. Add record: Type `CNAME`, Name `@`, Target — скопированный адрес туннеля, Proxy status `Proxied` (оранжевое облако), TTL `Auto`. Сохраните.
4. Если у записи `api` другой тип, возьмите Tunnel ID именно туннеля `pochva-ai` из его настроек и сформируйте `<Tunnel ID>.cfargotunnel.com`. Replica ID из списка подключений для этого не подходит. Токен туннеля сюда не вставляют.
5. Существующий `api` оставьте. При конфликтующей записи `@` сначала проверьте её назначение, не удаляйте её вслепую.
6. Проверьте https://pochva-ai.tech. Если браузер помнит прежний отрицательный DNS-ответ, подождите срок кеширования; в Windows можно выполнить `ipconfig /flushdns` и перезапустить браузер. Также проверьте с мобильного интернета. Если DNS уже отвечает, а возникает другая ошибка, проверяйте её отдельно.

Сайт использует относительные API-адреса: отдельная правка фронтенда и ослабление CORS не нужны. На новом домене потребуется войти заново, поскольку cookie входа относится к конкретному хосту. Это те же аккаунты и сохранённые беседы в той же базе. Гостевые идентификаторы и выбранное оформление браузер хранит отдельно для каждого адреса.

Изменения DNS выполняются в вашем Cloudflare. Наличие этих инструкций в репозитории само по себе DNS не меняет.
